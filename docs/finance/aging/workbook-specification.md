# FIN-AGING-0 · Deliverable A — Workbook Specification

**Source**: `TEST BALANCE AGEE CLIENTS.xlsx` (received 2026-07-29, analyzed at OOXML level —
every sheet, cell, style, merge, number format and chart definition was extracted from the
file's XML parts, not eyeballed in Excel).

**Provenance facts from the file itself**
- Generated by **openpyxl** (`docProps/core.xml` creator), last modified 2026-07-21 by a
  workstation on the accounting share `\\…\COMPTABILITE\COMPTA TRANSIT\`. The workbook is
  therefore *already* a rendered artifact of some upstream process — reproducing it
  programmatically is proven feasible because that is how it was made.
- Reporting date (« date d'arrêté ») embedded in the titles: **12/06/2026**. The workbook is
  a snapshot *as of* a stated date, not a live view. This confirms the requirement that the
  platform's aging engine take a configurable `reporting_date` rather than `now()`.

## ⚠️ Anonymization status of the received copy — and of this document

The received copy was partially anonymized: in **Données Brutes**, **Analyse Clients** and
**Dossiers Critiques**, identifying/financial cells (invoice number, dates, dossier, client,
amount) were blanked while derived cells (days overdue, bucket, risk, averages, percentages)
were left intact. **The anonymization missed data**: the **Graphiques** tab still contains the
real top-10 client names with amounts, and both analysis tabs retain real portfolio totals.

Because this repository is public, this document records **structure, styling and rules
only**. Real client names, monetary amounts and portfolio percentages are **not** reproduced
here. The reference workbook itself is **not committed**. Where a rule was verified
empirically, the verification method and result are stated without the underlying figures.

## Tab 1 — 📊 Tableau de Bord

**Purpose**: one-screen KPI header plus the seven-bucket aging summary.

**Structure** (`A1:G16`):
- `A1:G1` merged — title `TABLEAU DE BORD – RECOUVREMENT  |  Balance âgée arrêtée au
  12 juin 2026` (navy band, white 14pt bold, row height 36).
- `A2:G2` merged — subtitle `Service Recouvrement & Finance  —  Arrêté au 12/06/2026`
  (blue band, italic white).
- Rows 4–6 — **six KPI cards**, one per column A–F. Row 4 = label (light-blue band, 9pt navy
  bold), row 5 = value (33.9pt tall, 14pt bold white on the card color), row 6 = a 9.9pt
  spacer row, styled but empty. Every card cell is a single-cell merge (openpyxl artifact —
  harmless, but reproduced for fidelity).

| Card (col) | Label | Card color | Number format | Semantics (verified against other tabs) |
|---|---|---|---|---|
| A | `Total encours` | navy | `#,##0 [$FCFA]` | Σ outstanding over all rows of Données Brutes = Analyse Clients TOTAL C |
| B | `Nb factures` | blue | `0` | count of Données Brutes rows = Analyse Clients TOTAL B |
| C | `Nb clients` | blue | `0` | count of distinct clients = Analyse Clients data-row count |
| D | `Montant en retard` | dark red | `#,##0 [$FCFA]` | Σ outstanding where days overdue ≥ 1 |
| E | `Retard moyen` | red `9C0006` | `0" jours"` | mean of days overdue (see open question Q-04: population = all rows or overdue rows only — the anonymized copy's blanked value cannot distinguish) |
| F | `Montant > 1 an` | purple | `#,##0 [$FCFA]` | Σ outstanding where days overdue > 365 = Dossiers Critiques TOTAL F |

- Row 8 — header row of the **bucket summary table** (navy band):
  `Tranche d'ancienneté · Nb factures · Montant (FCFA) · Part encours · Nb clients ·
  Retard moyen · Niveau de risque`.
- Rows 9–15 — the seven buckets, one per row, each label cell filled with its bucket color
  (left-aligned) and the risk cell (col G) filled with the same color family:

| Row | Tranche (exact label) | Niveau de risque (exact label, with emoji) |
|---|---|---|
| 9 | `Non échu (≤ 0 j)` | `✅ Sain` |
| 10 | `1 – 30 jours` | `🟡 Faible` |
| 11 | `31 – 60 jours` | `🟠 Modéré` |
| 12 | `61 – 90 jours` | `🟠 Modéré` |
| 13 | `91 – 180 jours` | `🔴 Élevé` |
| 14 | `181 – 365 jours` | `🔴 Élevé` |
| 15 | `> 365 jours` | `⛔ Critique` |

  Value columns per bucket row: B count (`#,##0`), C amount (`#,##0`), D part of total
  (`0.0%`, stored as a fraction), E distinct clients, F average delay (`0" jours"` style
  family). All blanked in the received copy; semantics confirmed by the surviving `% Montant`
  column on the Graphiques tab, which carries the same distribution.
- Row 16 — `TOTAL GÉNÉRAL` (navy band; B/C/E aggregated, D = 100%).

**Classification**: every cell on this tab is **calculated** (aggregates of Données Brutes)
or **presentation-only** (labels, spacer rows). The only *parameter* is the arrêté date
embedded in the two title strings. Nothing on this tab is source data.

**Dashboard-vs-data label divergence (deliberate, must be preserved)**: the dashboard risk
column uses emoji labels (`✅ Sain` … `⛔ Critique`) while Données Brutes uses plain text
(`Non échu`, `Faible`, `Modéré`, `Élevé`, `Critique`). Same classification, two label sets.

## Tab 2 — 📋 Données Brutes

**Purpose**: the invoice-level fact table — one row per open (outstanding) invoice as of the
arrêté. **This is the tab the whole workbook derives from.**

**Structure** (`A1:I432`): title band `A1:I1` (`DONNÉES BRUTES – Recouvrement en cours –
Arrêté au 12/06/2026`), header row 2 (navy), **430 data rows** (3–432), zebra-striped
(`F2F2F2` / white). Autofilter across `A2:I432`. No total row on this tab.

| Col | Header | Format | Width | Classification (verified) |
|---|---|---|---|---|
| A | `Facture` | text | 20 | **entered/imported** — invoice number |
| B | `Date édition` | date `dd/mm/yyyy` (numFmt 14) | 13 | **entered/imported** — issue date |
| C | `Échéance` | date `dd/mm/yyyy` | 13 | **entered/imported** — due date |
| D | `Dossier` | text, centered | 16 | **entered/selected** — operational dossier reference |
| E | `Client` | text | 32 | **entered/selected** — client name |
| F | `Montant (FCFA)` | `#,##0` right | 16 | **entered/imported** — outstanding amount (see Q-01) |
| G | `Jours retard` | integer, risk-colored | 14 | **calculated** = arrêté − échéance (empirically verified, below) |
| H | `Tranche` | text, row-tinted | 20 | **calculated** from G (empirically verified) |
| I | `Risque` | text, risk-colored | 30 | **calculated** from H (empirically verified) |

**Row coloring rule**: G/I cells carry the *bucket* color fill (green → light green → amber →
orange-red → dark red); A–F/H alternate zebra. The color encodes the bucket, and it is the
row's most visible signal.

**Empirical verification performed on all 430 rows** (values G, H, I survived
anonymization):

- `G ∈ [−122, 2 505]`, all integers → G is a whole-day date difference; negatives are
  *future* due dates as of the arrêté.
- H↔G mapping is exact and exhaustive over the data: see the aging table in
  [aging-calculation-spec.md](aging-calculation-spec.md). Notably **G = 0 maps to
  `Non échu (≤ 0 j)`** — an invoice due *on* the reporting date is not overdue. 87 rows have
  G ≤ 0, so the boundary is well-exercised.
- I↔H mapping is exact: Non échu→`Non échu`, 1–30→`Faible`, 31–60 and 61–90→`Modéré`,
  91–180 and 181–365→`Élevé`, >365→`Critique`. Zero exceptions in 430 rows.
- No cancelled/paid/credit/zero rows are present-as-such: every surviving row carries a
  bucket, and the sheet title says « Recouvrement en cours » — the tab contains **open
  receivables only**. Paid and voided invoices are excluded upstream, not shown at zero.
- No dispute column exists anywhere in the workbook.

**Editability conclusions** (spec §2): A–F are the manual/imported surface the Finance
Manager maintains today; G, H, I are **always derived** and must never be manually entered
in the platform. There is no evidence of any field being edited after finalization —
the workbook has no lifecycle at all, which is precisely the gap the platform closes.

## Tab 3 — 👥 Analyse Clients

**Purpose**: per-client aggregation, ranked by outstanding amount.

**Structure** (`A1:G73`): title `ANALYSE PAR CLIENT – Classement décroissant par encours`,
header row 2, **70 client rows** (3–72) sorted **descending by Montant total** (verified: the
surviving `Part encours` fractions match the Graphiques top-10 fractions in the same order),
TOTAL row 73.

| Col | Header | Format | Classification |
|---|---|---|---|
| A | `Client` | text, width 36 | grouping key |
| B | `Nb factures` | int | calculated — count of the client's open invoices |
| C | `Montant total (FCFA)` | `#,##0` | calculated — Σ outstanding |
| D | `Retard moy. (j)` | int, risk-colored | calculated — mean of G over the client's rows |
| E | `Retard max (j)` | int, risk-colored | calculated — max of G |
| F | `Part encours (%)` | `0.00%` (numFmt 10) | calculated — C ÷ grand total (stored as fraction; **sums to exactly 1.0** across the 70 rows — verified) |
| G | `Niveau risque` | text, risk-colored | calculated — see rule below |
| — | TOTAL row 73 | navy band | B = Σ counts, C = Σ amounts, F = 1 (100%); D/E/G empty |

**Client risk rule — empirically derived, with a subtlety** (all 70 rows tested):
`Niveau risque = risk level of the bucket containing Retard moy.` **except** that clients
whose average is ≤ 0 are rated **`Faible`, not `Non échu`** (8 such clients in the data,
including averages as low as −44). The client-level scale therefore has **no « Non échu »
level** — its floor is `Faible`. D and E cells are *colored* by the bucket of their own
value. This floor rule is workbook fact, not our invention; its business intent is
open question Q-06.

**Relationship to other entities** (spec §3): grouping is by client name string in the
workbook; in the platform it becomes `client_id`. Invoices/balances come from the same rows
as Données Brutes; payments and credit notes only enter through the outstanding amount;
disputes and dossiers do not appear at client level in the workbook.

## Tab 4 — ⛔ Dossiers Critiques

**Purpose**: the escalation list.

**Inclusion criterion — exact, and the ONLY one**: the title states it —
`DOSSIERS CRITIQUES – Factures avec retard > 365 jours`. Verified: the tab holds **81 data
rows** (3–83), whose surviving `Jours retard` values range **366 → 2 505** and are sorted
**strictly descending**; 366 appears, 365 does not. There is **no amount threshold and no
other condition**. (81 also equals the count of `> 365 jours` rows in Données Brutes.)

**Structure** (`A1:H84`): dark-red title band; header row 2 (dark-red `C00000`, wrapped);
data rows striped `FCE4D6` / white with red-family accents; TOTAL row 84.

| Col | Header | Notes |
|---|---|---|
| A–G | `Facture · Date édition · Échéance · Dossier · Client · Montant (FCFA) · Jours retard` | same shapes as Données Brutes |
| H | `Commentaires` | width 40 — free-text collection note per invoice. Blanked in the copy; styled as a data column. Whether these are permanent collection notes or per-report annotations is open question Q-10. |
| Row 84 | `TOTAL – Dossiers critiques` merged `A84:E84` | F = Σ critical amounts (`#,##0`, red on `FCE4D6`); **G = count of critical invoices** (an integer in the days column — quirk to reproduce, not "fix") |

Fields per row: no responsible employee, no follow-up date, no escalation status —
those columns do **not** exist in the workbook. They exist in the platform's
`collection_follow_up` table already; wiring them into the module is listed under
*improvements*, separately from workbook reproduction (roadmap doc).

## Tab 5 — 📈 Graphiques

**Purpose**: chart data blocks + three charts.

**Cell structure** (`A1:D41`): title band `A1:D1`; **bucket block** rows 3–10
(`Tranche · Nb factures · Montant (FCFA) · % Montant`, one row per bucket, same seven
labels; `% Montant` = `0.0%` custom format, stored as fractions); **top-10 block** headed
`TOP 10 CLIENTS` (blue band `A30:C30` merged) with header row 31
(`Client · Montant (FCFA) · % Total`) and ten client rows 32–41 sorted descending. The
top-10 fractions equal the first ten `Part encours` values of Analyse Clients (verified) —
same calculation, sliced to 10.

**Charts** (from `xl/charts/chart*.xml` + `drawing1.xml`, all `oneCellAnchor`, legend right,
`varyColors=1`, data labels shown, both bar charts with **value axes deleted** — the data
labels replace the axis):

| # | Type | Title | Categories | Values | Anchor | Notes |
|---|---|---|---|---|---|---|
| 1 | bar, `barDir=col`, clustered, gapWidth 150 | `Encours par tranche d'ancienneté (FCFA)` | `A4:A10` (bucket labels) | `C4:C10` (amounts) | ~A12 | value labels `#,##0` |
| 2 | pie | `Répartition % de l'encours par tranche` | `A4:A10` | `D4:D10` (fractions) | ~M12 | labels General format |
| 3 | bar, `barDir=bar` (horizontal), clustered, gapWidth 150 | `Top 10 clients – Encours (FCFA)` | `A32:A41` | `B32:B41` | ~A44 | value labels `#,##0` |

No explicit series colors are set (theme-default `varyColors`); the platform renderer may
either accept theme defaults (faithful) or pin the risk palette (improvement — decision
D-08).

**Aggregation & filtering**: chart sources are the *precomputed* blocks on this same sheet;
charts never read Données Brutes directly. The web dashboard, Excel, PDF and print must
reproduce the same three visualizations with the same series meanings.

## Cross-tab dependency graph (as verified)

```
Données Brutes (430 invoice rows; A–F facts, G–I derived per row)
  ├─→ Tableau de Bord   KPI cards + 7-bucket aggregate table
  ├─→ Analyse Clients   group by client, rank desc by Σ outstanding
  ├─→ Dossiers Critiques  filter G > 365, sort G desc, + Commentaires column
  └─→ Graphiques        bucket block + top-10 block  ─→  the 3 charts
```

Every derived tab is a pure function of Données Brutes plus the arrêté date. That is the
report view model the platform must produce; the renderers then lay it out.
